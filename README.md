# NeuroPrep — Science-Backed Exam Preparation Platform

A professional, production-grade PWA for **CSS, PMS, FPSC, PPSC, AJK PSC** and 80+ exam bodies — **21,000+ curated MCQs** built on evidence-based cognitive science, with a full **eyes-free no-screen mode** for zero eye strain.

**Live:** https://psc-ajk.vercel.app/

## Quick start

```bash
# 1. Rebuild the sharded question banks (only needed after data/source changes)
npm run build        # → data/banks/builder/*.json + data/banks/manifest.json

# 2. Serve locally (any static server works)
npm start            # http://localhost:8765
```

No build step, no framework, no dependencies — vanilla ES modules, HTML and CSS.

## Deploying (Vercel)

The repository root **is** the deployable site:

- `index.html`, `styles.css`, `app.js` — the app shell
- `manifest.webmanifest`, `sw.js`, `icons/` — PWA
- `data/banks/` — sharded builder bank + manifest (generated by `npm run build`)
- `board/` — 601 board-subject files + `board/index.json` catalog
- `vercel.json` — clean URLs, cache headers, security headers, SPA rewrites

Import the repo into Vercel and deploy — zero configuration. All settings (clean URLs, caching, headers) are committed in `vercel.json`.

## Architecture

```
├── index.html            App shell — semantic, accessible, SEO + OG + JSON-LD
├── styles.css            Design system (CSS variables, 6 themes, load-aware)
├── app.js                Cognitive engine: Leitner, misconceptions, audio,
│                         visual/acoustic load, knowledge graph, Pomodoro,
│                         command palette, lazy shard loader
├── sw.js                 Offline: app-shell precache + runtime bank cache
├── manifest.webmanifest  PWA manifest (installable, shortcuts)
├── icons/                Generated brand assets (192/512/maskable/OG/favicon)
├── data/
│   ├── source/           Raw question bank (21k) — pipeline input
│   └── banks/            GENERATED: per-subject shards + manifest
├── board/                81 exam bodies, 601 subject files + catalog
└── tools/
    ├── build-banks.mjs   Data pipeline: shards + manifest + verification
    ├── schemas/          JSON schemas for question & subject data
    ├── legacy/           Standalone quiz builder (superseded by app.js)
    └── design/           Icon source files (gitignored)
```

**Data flow at boot:** `data/banks/manifest.json` (~1.3 MB, subjects/topics/counts) + `board/index.json` (catalog) → filters & counts render instantly. Question shards load **only** when a session needs them, in batches, with progress toasts — then live in memory and the SW runtime cache.

**Learning state** (Leitner boxes, misconceptions, session history) persists in `localStorage` and survives lazy loading via a question-id → subject index.

## Regenerating the data banks

Question data lives in `data/source/questions.json`. After editing it:

```bash
npm run build
```

This regenerates `data/banks/` (15 subject shards + manifest with per-topic counts) and verifies every file referenced by `board/index.json` exists — broken deploys fail at build time, not in production.

Board data is refreshed from the upstream API with:

```bash
node tools/fetch-subjects.js
```
